11 · States and rules

Five states, enforced server-side

The path uses five clear states. Locking is enforced on the backend, so hiding a button is never the only protection.

Visual language
Five states, one glance
Completed
Checkmark. Always reopenable for revision.
Current lesson
Highlighted with a “Continue” marker. Exactly one at a time.
Locked
Lock icon. Prerequisites not met; blocked by the server, not just hidden.
Revision
Dashed amber. Optional recap material, never blocks progress.
Assessment
Trophy. Unit or level check that validates understanding.
How locking really works
The server decides, the screen reflects it
Browser
Opens a lesson from the path or by direct link
Path API
Verifies the Supabase token, then checks prerequisites
Database
path_lessons · user_path_progress (clients can read, only the API writes)
UNLOCKED
Lesson content and exercises are returned. Correct answers never are.
LOCKED → 403
The request is refused and the student is sent to their current lesson. Same result for direct URLs and API calls.
COMPLETED
Server grades the attempt, records the score, unlocks the next lesson in one transaction.
Stays exactly as is: existing grammar and vocabulary, listening and pronunciation, level test, tools, Study Plan data and all user accounts. The new tables are additive.
